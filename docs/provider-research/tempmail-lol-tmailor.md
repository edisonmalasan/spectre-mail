# Provider research: TempMail.lol and Tmailor

**Investigation date:** 2026-11-22 (all retrieval timestamps below are UTC on that date, from the browser console clock and the probe responses).
**Researcher:** research sub-agent `research/tempmail-tmailor`, isolated worktree.
**Scope:** the two candidates named in `docs/GOAL.md` §3 — TempMail.lol (`https://tempmail.lol/api`) and Tmailor (`https://tmailor.com/temp-mail-api/`). Receive-only disposable mail; no sending, no account automation, no quota exhaustion, no terms/CAPTCHA/login bypass.
**Redaction:** bearer tokens, access tokens and full generated addresses are redacted in every quote below. Domains and HTTP response metadata are not secrets and are quoted verbatim.
**Evidence vocabulary:** `MEASURED` = command/browser output captured this date; `DOCUMENTED` = official page text quoted; `NOT MEASURED` = no instrument produced a result; `REVIEW REQUIRED` = third-party permission is ambiguous or adverse, never a PASS.

Two counters are kept apart throughout, per GOAL §3/§8: **provider count = 2 researched**, and **domains with verified real incoming mail = 0** (no authorised external sender was available; a successful create is never recorded as a delivery proof).

## 4. Blockers, unknowns, and REVIEW REQUIRED items

1. **REVIEW REQUIRED — TempMail.lol terms.** "making your own temporary email website" is given as an example of prohibited re-selling; commercial use requires explicit permission, Plus, or Ultra; ToS separately prohibits "Using our API to create your own API or service". Whether a paid Plus/Ultra subscription would license a _competing_ product is unresolved. Do not treat as PASS.
2. **REVIEW REQUIRED — Tmailor terms.** API terms limit use to testing services the customer owns or is allowed to test and prohibit sublicensing; no affirmative permission for a competing temp-mail product was found.
3. **NOT MEASURED — extension host-permission behaviour for both providers.** No unpacked-Chromium harness in this isolated worktree (no `node_modules`; installing Playwright Chromium is outside the read-only research brief). The measured third-party-origin CORS failures must not be silently transferred to, or waived for, the extension context.
4. **NOT MEASURED — Tmailor API liveness / read-delete-return shapes.** No key; OpenAPI spec unreadable (403 to shell, YAML unsupported by webfetch, download aborted in browser). Endpoint paths beyond `POST /v1/mailboxes` come from SDK prose only.
5. **LIVE DELIVERY NOT VERIFIED for both.** Requires an authorised external sender (GOAL §8.4); this is a human/authority dependency, not a research gap to paper over.
6. **Architecture incompatibility (TempMail.lol).** Reads consume/delete messages and the free inbox lives one hour; this conflicts with repeatable list/read, reload restore, and the existing `MailProvider` contract's stateless `listMessages(mailbox)`/`getMessage(mailbox, id)` shape (`packages/providers/src/contract.ts`).
7. **No credential-delivery design (Tmailor).** A bearer key plus a one-IP allowlist cannot be shipped in a client-only product; GOAL §4 requires an approved design before any user-owned-key model is considered.

**Overall:** neither candidate is recommended for integration on the evidence available. TempMail.lol website is **BLOCKED** by measured CORS and adverse terms; its extension case is **NEEDS AUTHORIZATION** and also conflicts with the contract's read semantics. Tmailor is **BLOCKED** on the website by measured CORS and **NEEDS AUTHORIZATION** everywhere else (key + IP allowlist + unresolved third-party permission).
