## 0. Verdict in one paragraph

The repository already has the **shape** GOAL §6–§7 asks for: one `MailProvider` contract with two stateless adapters, a bounded domain catalog, exact provider→mailbox routing, per-client provider lists, a four-action website toolbar with an Automatic/manual domain picker, and a website `Change` path with generation-token, coalescing and stale-response guards. What it does **not** have is the **provenance and truthfulness vocabulary** the goal names: `Domain` carries provider identity and a crude active/expiry pair but no discovery time, supported runtime, lifecycle status, free/premium distinction or capability flags; the catalog hides its fetch time and has no cross-provider aggregation; "available / provisioned / delivered" is not a modelled distinction; bounded retry/backoff conflicts with the existing "throttling is surfaced, not silently retried" requirement and must be reconciled in OpenSpec rather than coded; and the **extension popup has no Change path at all** — its domain list appears only on first creation. The smallest coherent change is therefore a shared-model + provider-layer provenance slice, a spec reconciliation slice for fallback/retry truthfulness, and a separate extension-UX slice that reuses the website's already-proven guard pattern. These are independent in file ownership after the shared slice lands.

## 2. What is missing, and the smallest coherent change set

### 2.1 The gap list (ordered by dependency)

**G1 — Provenance fields (shared model).** `Domain` needs explicit, provider-sourced discovery time, a supported-runtime marker, a lifecycle/status value richer than `active`, and capability flags. The single existing field that must **not** be invented is free/premium: no measured provider response in this repository carries such a flag (`docs/PROVIDERS.md:66-165, 378-545`; fixtures at `packages/providers/src/fixtures.ts:28-36, 90-131`). A free/premium field may only be added when a candidate research worker produces a served, dated source. **NOT VERIFIED** whether any GOAL §3 candidate exposes one.

**G2 — Catalog aggregation and identity.** The catalog must (a) expose provenance rather than hide `fetchedAt`, (b) aggregate multiple provider catalogs without collapsing identically spelled domains across providers, and (c) apply runtime compatibility filtering. GOAL §6 line 89 is **ambiguous**: "deduplicate catalog options without treating identically spelled domains from different providers as interchangeable". The two readings — keep both entries with distinct provider ids, or drop duplicates while retaining owning-provider identity — produce different picker rows. **Decision required from the orchestrator; not guessed here.**

**G3 — Truthfulness tri-state.** `available in provider catalog` / `mailbox successfully provisioned` / `real external mail received` must be three distinct, reportable states. The first two are reachable from existing values; the third must remain `LIVE DELIVERY NOT VERIFIED` until a sender exists (`docs/ux-reference/m21-coverage-matrix.md:44, 78-84`).

**G4 — Bounded retry/fallback reconciliation.** GOAL §6 line 93 asks for "bounded retries, timeouts, appropriate backoff/rate limiting and fallback"; the promoted requirement forbids silently retrying throttling (`openspec/specs/provider-abstraction/spec.md:152-161`) and `provider-adapters` forbids failover outside creation (`openspec/specs/provider-adapters/spec.md:354-386`). Adding a retry loop in `manager.ts` would break both. The coherent reading is **bounded, visible fallback among providers at creation only**, with each attempt at most once and the throttle surfaced verbatim — which is what `manager.ts:69-113` already does, except that the multi-provider composed `Error` destroys the normalized `code` (`manager.ts:86-112`). Fix that, and state the rule in the spec; do not add a silent loop.

**G5 — Extension Change UX.** The website already has Automatic/manual Change, stability during Refresh, reader clearing, double-click coalescing and out-of-order guards. The extension has none of these in its popup. Reusing `useMailboxSession`'s pattern verbatim is **not** possible without deciding where the generation token lives: the extension popup has no hook equivalent and no `replace` call today. The minimal design is a thin local guard in `Popup.tsx` over `session.replace(domain?)`, with the same "keep previous mailbox until provider confirms" semantics that `packages/mailbox/src/session.ts:505-507` already gives for free.

**G6 — Capability discovery for domains.** `supports()` currently knows only deletion. If the picker is to hide manual choice when a provider cannot create on a chosen domain, that fact must be a typed capability answer, not an `id === "guerrilla"` test in a client (which would also be a second spelling of provider knowledge and would likely trip `tests/architecture/boundaries.test.ts:4018` "stops a client restating a value a shared package already owns").

## 4. GOAL §8 — constraints and the new cases needed

### 4.1 Existing instruments that already constrain the work

### 4.2 New cases required

**Contract / unit (per GOAL §8.1):**

1. `Domain` provenance round-trip: discovery timestamp, runtime marker, lifecycle status and capability flags survive `listDomains()` → catalog → client, and a domain from provider A is never handed to provider B's `createMailbox` (extends `catalog.test.ts` and `packages/providers/src/conformance.test.ts`).
2. Pagination: follow `hydra:next` across the synthetic two-page fixture; stop at the bound; report truncation rather than silently presenting a partial list as complete.
3. Free/premium and retired-domain filtering — **only after** a provider source exists; until then a test that asserts "premium excluded" would be a test with no production input and must be recorded as NOT VERIFIED, not written as a fake.
4. Malformed responses, missing timestamps (`toReceivedAt`/`toEpochMillis` returning `null`, never `0`), 429/5xx classification, cancellation and stale-response isolation at the **popup guard** (website already has it at the hook).
5. Bounded fallback preserves the normalized `code` when several providers are configured — the counterfactual in `manager.ts:86-112`.
6. Tri-state reporting: catalog availability, provider-confirmed provisioning, and `LIVE DELIVERY NOT VERIFIED` are distinguishable strings/states in both clients.

**Browser (per GOAL §8.3):** 7. Website CORS measured from a real page for **each newly proposed provider** — Node or a recorded fixture cannot substitute (`docs/PROVIDERS.md:32-63, 185-200`). This is other workers' research output; do not pre-write a passing case. 8. Extension unpacked-Chromium lifecycle for the Change path with minimal host permissions (`apps/extension/static/manifest.json:14-15` — today `storage, alarms, notifications, sidePanel` and two wildcard provider origins). 9. Double-click and out-of-order: two rapid Change presses issue one creation; a late response from the older request does not replace the newer mailbox or resurrect an opened message — browser-level counterparts of the website hook cases. 10. Keyboard, focus, reduced-motion and narrow-surface render of the picker; no layout shift on Copy feedback or Refresh; no sixth region.

**Not a gate here:** live external mail (GOAL §8.4) stays BLOCKED until an authorized sender exists (`m21-coverage-matrix.md:44, 78-84`); a recorded fixture must never be relabelled as live evidence.
