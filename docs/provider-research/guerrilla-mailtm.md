**Report date:** 2026-11-22 (all live retrievals and probes below carry their own UTC timestamp).
**Role:** research worker; this file is the only repository file I own or edited.
**Base:** `main` + the GOAL commit (`e825355`); branch `research/guerrilla-mailtm`.
**Authority:** `AGENTS.md` (protected paths), `docs/GOAL.md` §§3, 8, `docs/ORCHESTRATION.md` §2. I did **not** edit `docs/PROVIDERS.md`, product code, OpenSpec artifacts, the roadmap, `AGENTS.md`, CI, design records, or another worker's report.

## 0. Evidence rules applied

- Every claim below names an official source URL and retrieval date, or a verbatim command + output.
- A **recorded fixture**, a **successful create**, and **real incoming mail** are three different claims and are reported separately (GOAL §3, §8). I created two bounded anonymous Guerrilla sessions (§2.2, §2.3) and **no** Mail.tm account; **no live external mail was sent in this research**, so nothing here upgrades either provider's delivery status.
- Third-party / competitive permission that docs do not clearly grant is marked **REVIEW REQUIRED**, never a pass. No provider whose permission is ambiguous is given a final `SUPPORTED` without that flag.
- Browser CORS was measured from a **real Chrome tab** through the T3 `browse` tools, not from Node. Extension host permissions were measured in a **real Playwright-launched Chromium MV3 context**, not inferred from headers. Node-only calls are labelled "API probe" and are **not** offered as CORS evidence.

### 2.2 Guerrilla address assignment — Node API probe, **one** bounded anonymous session

```

retrievedAt=2026-11-22T03:41:12.868Z
url=https://api.guerrillamail.com/ajax.php?f=get_email_address

access-control-allow-origin=*
```

Findings: provider assigns the whole address (no caller domain choice), on `@guerrillamailblock.com`, the same domain S1 uses in its `set_email_user` example. `ACAO: *` with **no** `ACAC` — exactly why the adapter persists `sid_token` and never a cookie (`guerrilla.ts:9-13, 121-125, 369-372`). Two `Set-Cookie` headers were present and **redacted** (secret material). No rate-limit header on this call, consistent with S1's "we do not publish our rate limits".

### 2.3 Website-origin CORS — measured in real Chrome (T3 `browse`)

A minimal HTML page was served from `http://127.0.0.1:51947/` (random port, **not** 4173), opened in my own tab group `provider-research-guerrilla-mailtm`, and the fetches were issued in the page's **main world**. The tab was closed and the server stopped after the measurement.

```
retrievedAt=2026-11-22T03:41:39.011Z
pageOrigin=http://127.0.0.1:51947
checks:
  guerrilla-GET-get_email_address  -> RESOLVED, status 200, type "cors",
                                      content-type application/json,
                                      bodyKeys ["email_addr","email_timestamp","alias","sid_token"]
  mailtm-GET-domains               -> REJECTED, "Failed to fetch"
  mailtm-POST-accounts (preflight) -> REJECTED, "Failed to fetch"
```

Interpretation: from an ordinary third-party web origin, Guerrilla grants cross-origin reads; Mail.tm grants none, and its preflighted `POST /accounts` fails before any account is created. This independently confirms `docs/PROVIDERS.md` §1 and is **browser evidence**, unlike §2.1's Node call. (This measurement created one further anonymous Guerrilla session — total bounded probes: 2.)

### 2.4 Extension host permissions — measured in real Chromium MV3 (Playwright 1.63.0)

A throwaway MV3 extension with a module service worker was launched with `--load-extension=<ABS>` and `--disable-extensions-except=<ABS>`, `channel: "chromium"`, and the fetch was evaluated **inside the service worker** with `credentials: "omit"`. Three manifests differing only in `host_permissions`; separate profiles per case. Fixture and runner lived outside the repository (`%TEMP%/opencode/ext-fixture`, `ext-cors-run.cjs`).

```
hostperm-wildcard | {"swOrigin":"chrome-extension://jlfocongelehgonhfgccpbbjpalecpla","guerrilla":{"ok":true,"status":403},"mailtm":{"ok":true,"status":200}}
hostperm-slashless| {"swOrigin":"chrome-extension://jlfocongelehgonhfgccpbbjpalecpla","guerrilla":{"ok":false,"error":"Failed to fetch"},"mailtm":{"ok":false,"error":"Failed to fetch"}}
hostperm-none     | {"swOrigin":"chrome-extension://jlfocongelehgonhfgccpbbjpalecpla","guerrilla":{"ok":false,"error":"Failed to fetch"},"mailtm":{"ok":false,"error":"Failed to fetch"}}
```

Wildcard patterns: `https://api.mail.tm/*`, `https://api.guerrillamail.com/*`. Slash-less: the same two origins with no `/*`. None: `https://example.com/*`.

Notes that keep the claim honest: Guerrilla's `403` is the **host root** (`https://api.guerrillamail.com/`), deliberately chosen so this probe allocates no third mailbox — a 403 is a _response_, proving the origin was reached, not a permission refusal. Mail.tm's `200` is the same read-only `/domains` call as §2.1. Both slash-less and no-permission cases produce the opaque `TypeError: Failed to fetch`, which is why the shipped manifest must use the `/*` form; the shipped manifest does (`apps/extension/static/manifest.json:15`). The first run of this harness reported `NO SERVICE WORKER` for all three cases (extension silently loaded nothing); aligning with the repository's own probe — `channel: "chromium"`, module worker, `--no-first-run` — made all three load. **The failed first run is recorded rather than discarded**: an extension that silently loads nothing is the exact failure mode this check exists to detect.
