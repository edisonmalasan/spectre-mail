# GOAL report — M25: Authorized free provider expansion & DropMail pilot

Date: 2026-11-23. Source objective: `docs/GOAL.md` (M25, merged in PR #268). This is the auditable GOAL §7 handoff for M25. Every verdict names its dated evidence and the runtime it covers, and no row is upgraded because a neighbouring row passed.

Evidence labels: **MEASURED** = instrument output on this machine; **DOCUMENTED** = verbatim from an official source retrieved on the date given; **INFERRED** = reasoning labelled as such; **NOT VERIFIED** = no measurement exists; **BLOCKED** = an arm deliberately not completed, with its resume condition named. `PERMISSION REQUIRED` and `REVIEW REQUIRED` are permission-class BLOCKED verdicts, never PASS; `TECHNICALLY BLOCKED` is the technical-class BLOCKED verdict. A technical-feasibility PASS is **not** an authorization PASS.

## Verdict: **PARTIALLY MET**

The authorization-free work succeeded: the DropMail OAuth substrate measured PASS in a real unpacked Chromium, the ready-to-send authorization inquiry was drafted, Mail.gw and Mail.tm were re-read from official sources, and the quarantined probe was registered in the architecture boundary suite. No new provider can be enabled. Every new-provider permission gate is BLOCKED or REVIEW REQUIRED, website CORS stays BLOCKED, and the token-dependent arms require a human login and a per-user token. No shared token was generated, committed, logged or shipped. **No provider is production-integrated or advertised as supported**, and no provider change was made in this milestone.

## C. The eight GOAL §7 gates

### 1. Official usage permission, free-tier suitability and attribution — **BLOCKED** for new providers

No ambiguous claim was marked passed. DropMail is **PERMISSION REQUIRED**: no ToS at 17 probed paths, a 2017 privacy template, and a developer invitation that is technical/operational guidance rather than a grant. Mail.gw is **REVIEW REQUIRED**: its docs forbid selling a client that _exclusively_ uses its API, but give no affirmative grant to a free competing multi-provider client, and three terms routes 404. Guerrilla's terms, read 2026-10-16, have no attribution clause but remain silent on redistribution and competitive use — **NEEDS AUTHORIZATION**.

Mail.tm's current official docs (`https://docs.mail.tm/`, retrieved 2026-11-23) state verbatim under **Attribution required**:

> "If you use our API, link back to mail.tm somewhere visible."

That attribution is **DOCUMENTED but NOT IMPLEMENTED**. Implementing it needs an approved UI change and an OpenSpec amendment: `openspec/specs/privacy-disclosure/spec.md` currently forbids stating an attribution obligation in one direction while also requiring the terms to be quoted, so a bare edit would make the promoted spec contradict itself. Competitive-use permission remains unresolved. **No provider change was made here.**

### 2. Valid live domain inventory and provisioning path — **historical / NOT VERIFIED**

DropMail's 19 domains (15 permanent, 4 rotating) are a dated 2026-11-22 snapshot; current inventory is **NOT VERIFIED** because every `domains` request needs a token and none was held or generated. Mail.tm's single domain is inherited from 2026-11-22 and not re-measured. Guerrilla publishes no domain API. Mail.gw's inventory is **NOT MEASURED** because the host answered nothing. **ZERO new domains were added.**

### 3. Browser tests — **extension OAuth substrate PASS; website CORS BLOCKED**

The extension's OAuth substrate passed in a real unpacked Chromium: `identity.getRedirectURL` and `launchWebAuthFlow` produced `https://<id>.chromiumapp.org/callback`, PKCE S256 was generated and verified, RFC 8414 metadata answered HTTP 200, dynamic registration answered HTTP 201 with no client secret, and a local redirect to the generated URI was intercepted successfully. This is a **technical-feasibility PASS only**.

DropMail's website remains **BLOCKED**: no `Access-Control-Allow-Origin` or `Access-Control-Allow-Headers` on GET or OPTIONS `/api/graphql/-` (HTTP 401, 2026-11-23 header-level check); the real-page cross-origin failure was measured 2026-11-22 and was **not re-run today**. No proxy or backend was added. Mail.gw is **TECHNICALLY BLOCKED** on three paths and its browser CORS is **NOT MEASURED**, not denied. The existing Guerrilla website and extension integrations and the Mail.tm extension integration were preserved unchanged.

### 4. Secure per-user OAuth / token flow — **PARTIAL; no shared secret**

The substrate above is measured. Token exchange, revocation/expiry, the five minimum GraphQL operations and token restoration across sessions are **BLOCKED / NOT VERIFIED**: they need a human login and a per-user token. Dynamic registration returned a client id with **no client secret**; only redacted shape was recorded. **No shared token was generated, committed, logged or shipped**, and a technical-feasibility PASS is **not** an authorization PASS.

### 5. Contract tests — **NOT VERIFIED for any new provider**

No adapter was added, so the create/auth/restore/list/read, pagination/health/expiry, 429/5xx, malformed content, concurrency and fallback contract suite was not extended or run against DropMail, Mail.gw or any other new provider. ## G. Remaining risks and human dependencies

**Risks.** Authorization is unresolved for every new provider, so further integration code would create surface that cannot ship. The no-backend/no-proxy rule makes DropMail's website CORS failure a hard technical block, not a tunable one. Any shared token would violate the product's per-user credential rule; the probe deliberately holds no credential and its client id was redacted and not stored. The Mail.tm attribution obligation is documented and unimplemented, and the promoted `privacy-disclosure` requirement currently conflicts with quoting it, so an implementation without an amendment would contradict the spec. Mail.gw documents 10-minute deletion and non-renewed domains (not measured), which would need truthful surfacing if it ever became reachable. The quarantined probe loads a throwaway Chromium extension declaring `identity`, a permission the product must not ship; its registration in `QUARANTINED_PROBES` is what keeps it out of suites and packages. The load-driven `onTaskUpdate` flake means one green run is not a determinism claim. Browser evidence is from headless Chromium on one machine; nothing about a headed desktop, another engine, a packed extension or a real person seeing an OAuth page was measured.

**Human dependencies that cannot be completed autonomously:**

1. The provider answer — the owner sends the §E inquiry and obtains written permission from DropMail; written clarifications are also needed from Mail.tm and Guerrilla.
2. A human DropMail login for their own account to obtain the per-user token that unblocks the token exchange, revocation/expiry, GraphQL and restoration arms.
3. Approval of the Mail.tm attribution UI placement and copy, together with the OpenSpec amendment that reconciles the two promoted requirements.
4. Final visual and functional acceptance of the built website and extension by a person.

## Final answer

**PARTIALLY MET.** The research, feasibility proof and preparatory work succeeded, but no new permitted provider can be enabled and the mandatory permission, token, contract-test and live-delivery gates for new providers are unresolved. No provider is production-integrated or advertised as supported.
