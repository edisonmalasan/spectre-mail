# Design system

The approved visual direction for SpectreMail is **Spectral Swiss Utility**, and this file
is its contract: what the tokens are, what each one is held to, and what this repository
does and does not verify about them.

It exists for two readers. A **maintainer** changing a value needs to know which test is the
arbiter — the rule here is that a token's test is not taste in isolation. An **agent**
picking up a task needs to know which decisions are already made, so that a new surface is
built from the scale rather than inventing a value that looks close.

## Where the values actually live

**`packages/ui/src/tokens.ts`, and nowhere else.** This document's token tables are generated
from it. A hex, a size, or a duration written into this file's prose would be a second
declaration of a design value, and this repository has refused that pattern since M0 — twice
over, in a `SpectreStorage` record and in the provider wire format.

Two files are projections of `tokens.ts`, and both are checked against it:

- **`packages/ui/src/tokens.css`** — what the page loads. Generated by
  `packages/ui/scripts/emit-tokens.ts`, and `tokens-css.test.ts` asserts the committed file
  is byte-for-byte what its source renders.
- **The token tables below** — generated by `packages/ui/scripts/emit-design-doc.ts`, and
  `design-doc.test.ts` asserts the same byte-for-byte property against this file.

**So the chain has no unverified link in it.** A value is written once, in TypeScript; the
stylesheet and this document are both computed from it; and both are asserted, not reviewed.

## What belongs in the token layer

Anything a second client will need and a human will want to change: colour, type, spacing,
radius, weight, motion.

**Not** layout, and **not** component styles. Layout is a client's business — the website
and the extension lay out differently, and a shared layout is a shared assumption neither of
them has agreed to. Component styles live in the client that renders the component.

## The rules a token must follow

**A token is a scale step, not a value.** `space-5` is `1.5rem`, and `space-6` is `2rem`;
there is no `space-5.5`. `AGENTS.md` names inconsistent radius, spacing, border,
typography, and colour systems as things to avoid, and an inconsistency nobody can see is one
nobody can keep.

**A colour that carries meaning is held to a ratio.** Every ink and every identifying
boundary in the palette is declared in `packages/ui/src/pairs.ts` with the threshold it is
held to and the reason, and `pairs.test.ts` asserts it in **both** schemes. A colour held to
no threshold is **listed** in a table below with its reason — an omission reads as an
oversight, and the next person to move it would find a red test with no explanation.

**The dark scheme is declared, not derived.** No filter, no inversion. A dark scheme
produced by rearranging the light one is the light one, and it fails contrast somewhere
unremarkably. Both schemes are declared as their own values and both are checked.

**No remote asset.** No webfont, no `@font-face`, no CDN. Three independent reasons, any
one of which would be sufficient:

1. `build-and-verification` requires a browser check to reach **no third-party origin**, and
   a remote stylesheet or font makes every existing browser spec fail — not by being wrong,
   by being unable to load.
2. A remote font hands a third party the visitor's IP address on page load, in the one
   product whose stated subject is _what this device keeps_. The contrast between that and
   the local-data region is the point of the product.
3. A font binary is an unmeasured runtime dependency: no test here would know what it is.

So `font-sans` is a **system grotesk stack**. The Swiss character comes from the grid, the
type scale, the weight contrast, and the whitespace — all four of which are present in this
file's tables. A later change can install Geist properly, self-hosted, by editing **one**
value in `tokens.ts`, and no other file needs to know.

## Accent

rather than a near neighbour of it. That identity is declared in `tokens.ts`, not a
coincidence.

**Where the accent may go is `DESIGN.md`'s to say, and it says it once** — five jobs, in a list
it declares closed: **identity**, **verification**, **state**, **forward motion**, and
**depiction**. This document keeps no second list beside that one. It keeps a **measurement**:
every declaration in either client's stylesheet that names one of the four accent tokens, with
the job that declaration serves.

**The table is an inventory and `tests/architecture/accent-inventory.test.ts` holds it to the
tree in both directions**: a declaration added to a stylesheet and not here fails, and a row
here that no stylesheet carries fails. **The Job column is not machine-checked**, because which
job a declaration serves is a judgement, and a rule that nailed it down would be a list of
exemptions dressed as a measurement. What the rule does require is that every row carries one.

**And the measurement has a finding: the tree and the record disagree, in two ways, and both
are recorded rather than repaired.**

- **Three declarations are on none of the record's five jobs.** `.confirmation`'s background
  tints the region that asks _do you want to remove this?_; `.steps__name` tints the label of a
  step; `.reasons__claim` tints the term of a reason. A tinted question and a tinted
  enumeration are not a verification, not a state, and not forward motion.
- **The ring is a job the list does not carry.** `DESIGN.md` calls it _a fourth job rather than
  a brightness of the same one_ two sentences above the list, and the list of five does not
  name it — so the paragraph and the list beneath it count to different numbers.

**Neither is repaired here.** Moving three declarations off the accent changes what the page
looks like, and widening the record changes what it claims; both belong to a change that owns
the visual surface. **This section's job is that the disagreement is measured and named rather
than inherited.**

**The list this section used to carry was wrong in three ways, and all three are the same
shape**: a second list beside an authority drifts from it, and nothing says which one wins. It
said _primary action_ and _brand mark_ had **no home on the page yet** — both had one, and the
claim had been false since the slice that added them. It said **five declarations** used the
accent while omitting every `--surface-accent` and `--ink-accent` use, so its count described a
scan narrower than its own subject. And it called `.link__host` _a reading, not compliance_ —
the record names a link's host outright, so the apology defended a disagreement that had already
been resolved. **Measuring the tree replaced all three.**

A row that carries a verification is marked by a **rule**, not a recolour, so its text colour
does not change and the words remain the signal. The words were there before any stylesheet.

## Focus

The focus indicator is `2px` of `--focus` at a `2px` offset, on `:focus-visible` rather
than `:focus` so that a mouse click does not leave a ring behind while a keyboard press
always does.

**`outline: none` and `outline-width: 0` are forbidden** in any shipped stylesheet, and
`tests/architecture/boundaries.test.ts` fails the build on either, in every spelling. There
is one deliberate exception, documented in the rule itself: `outline: 2px solid transparent`
cannot be detected by reading a declaration, because `transparent` is a perfectly valid
colour. **That case is caught by the browser tier instead**, which reads the resolved
outline — style, width, and colour — on every control the page offers.

### Motion

**One materialisation, three entrances.** The mailbox address, an inbox row, and a
rendered verification code each arrive the same way: `opacity 0 → 1`, the declared blur
to zero, the declared rise to nothing, on `--ease-standard`. The two singular moments use
`--duration-base`; the inbox row uses `--duration-fast`, because rows arrive in bursts and
a queue of half-materialised rows reads as lag rather than as arrival.

**`prefers-reduced-motion: reduce` removes the animation.** Not a shorter duration and not
a `0.01ms` substitute — no animation at all, so "stopped" is the literal rendering rather
than a duration small enough to be called stopped. No fill mode is declared, and none is
needed: each element's own declarations already equal the animation's final frame, so
finishing the animation and having no animation are the same rendering. That is what makes
removal correct rather than a compromise.

**Two things this table does not describe.** Motion is **entrance only** — an element the
client has unmounted is gone before any transition can run, so the roadmap's
_"materialize/disappear"_ delivers only the first half. And there is **no `transition`**,
so the reduced-motion block governs animation alone and nothing here claims otherwise.

## What is verified, and what is not

### Verified, by a named instrument

- **Every declared colour pair meets its declared threshold, in both schemes.** Pure WCAG
  arithmetic over two hex values, in `packages/ui/src/pairs.test.ts`. This is the strongest
  instrument available for that claim: it asserts a ratio to two decimal places rather than
  "it looks legible".
- **The committed `tokens.css` and the tables above are byte-identical to what their source
  renders.** Otherwise they would be two declarations of one truth.
- **Every `var()` in a shipped stylesheet resolves to a declaration**, either in the token
  layer or earlier in the same file. A misspelled token would otherwise fall back to
  nothing, silently.
- **No shipped stylesheet or entry document reaches another origin.**
- **Every class hook a client renders is selected by a stylesheet.** Read from the syntax
  tree, not by pattern.
- **Every control the page offers is keyboard-reachable and draws a visible focus
  indicator**, in real Chromium, on the built page. The reading is the _resolved_ outline,
  compared against the same control unfocused — which is what makes a permanent outline
  fail rather than pass.
- **The three entrances carry the token layer's own motion values, and
  `prefers-reduced-motion: reduce` removes every animation on the page.** The durations and
  the easing are read from what each element _resolves to_ and compared against a probe
  declaration written in terms of `var(--duration-*)` and `var(--ease-standard)`, so the
  claim is the linkage and not a restatement of the numbers. Under the preference, the check
  sweeps **every element in the document** rather than the three selectors — and a
  **positive control** runs the same sweep without the preference and requires it to find
  the animations, which is what stops "nothing animates" from passing on a page where nothing
  animates either.
- **A row already on the page is not re-materialised by a later poll.** Established by
  **element identity**, not by appearance: a marker is set on a row's node before a second
  listing and must still be on it afterwards. A settled row and a re-materialised row look
  identical, so a visual check would have passed on the defect this rule exists to catch.
- **The keyframes reference the token layer rather than a literal.** Read from the CSSOM,
  which reports `blur(var(--blur))` and `blur(6px)` as the two different things they are.

### **Not** verified, and stated rather than implied

- **How SpectreMail looks.** No test in this repository reads a rendered pixel's colour.
  The palette is arithmetic and the ring is a computed style; both are exact about what they
  measure and silent about whether the result is _good_. Judging that is a human looking at
  the page, and this change does not automate it or pretend to.
- **How the motion looks.** The same shape, a third time. The motion checks read resolved
  values and the CSSOM, so they establish that the right animation runs for the right length
  and stops when asked. Whether 4px of rise and 6px of blur read as _restrained_ or as
  _fussy_ is a human judgement, and the roadmap's word for it — _"subtle"_ — has no
  instrument here. A blur on text is also a real legibility cost for the length of the
  entrance; that cost is accepted, and accepted is not the same as verified.
- **Exit motion.** The roadmap says _"materialize/disappear"_ and only the first half ships.
  An element the client has unmounted is gone before any transition can run, so the second
  half is not a CSS omission to be tidied up later — it is a different piece of work with
  its own verification. Nothing in this document implies it exists.
- **Firefox and WebKit.** One engine is configured, deliberately. Adding a project per engine
  would turn "verified" into "verified somewhere" without adding evidence about the claim.
- **A real provider.** The browser tier serves **recorded** provider responses, so nothing
  here has ever reached Guerrilla Mail. `use it externally` remains open, unchanged by this
  milestone.
- **The live polling cadence.** Unchanged by this milestone, and worth restating here
  because a styling milestone is a good place to forget it: nothing in this repository has
  watched a real provider respond to being polled every five seconds.
- **Blocked `deleteDatabase`.** Still a `fake-indexeddb` measurement. The browser tier does
  not produce that event.
- **`transition`.** This slice declares none, so the reduced-motion block governs animation
  alone. An element with no transition reports `transition-duration: 0s`, which means a check
  asserting that would pass on a page with no transitions at all — so the requirement says
  nothing about transitions, and the browser sweep carries it as a tripwire that starts
  reporting the day one exists.
